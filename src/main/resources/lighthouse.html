The lifecycle

Start an expedition to see Temporal in action

The browser starts a workflow. A worker picks up its tasks and runs the Java code.

Start→Worker→Workflow
Workflow · the keeperCoordinates rooms, tracks answers, waits for messages, and chooses the next step. Its decisions must be replayable.
Worker · the lighthouse crewThe Java process you started. It polls the lighthouse-quest task queue and executes workflow and activity tasks.
Activity · real workRoom setup and beacon repair run as activities. They can fail independently, so Temporal retries them.
Signal · your actionAnswer and hint buttons send signals to the open workflow. Temporal records each signal in its event history.
Durable timer · the storm clockThe ten-minute wait is stored by Temporal. It does not occupy a Java thread, and it still expires if the worker is stopped.
What if I stop the worker?

The workflow history, signal, and timer remain in the Temporal service. Restart the worker and it replays that history, then carries on. Open Temporal Web UI → the workflow → Event History to inspect the recorded steps and activity attempts.
